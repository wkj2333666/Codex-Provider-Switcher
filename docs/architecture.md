# Architecture

Codex Provider Switcher is a WebSocket message-policy proxy between Codex
Desktop Remote SSH stdio and one app-server Unix socket.

## Transport Boundary

`codex app-server proxy` does not expose JSONL. Its stdin/stdout is a raw HTTP
Upgrade followed by WebSocket frames, and the official implementation copies
those bytes to and from the Unix socket. Stock Desktop uses
`codex app-server proxy` without `--sock` and relies on Codex's default control
socket resolution.

The corrected transport terminates both WebSocket connections:

```text
Desktop stdio WebSocket
    |
    v
HTTP Upgrade -> downstream WebSocket -> JSON-RPC policy
                                         |
                                         v
                              upstream WebSocket over UDS
                                         |
                                         v
                                   app-server
```

The upstream Unix-socket handshake succeeds before Desktop receives `101
Switching Protocols`. An invalid downstream Upgrade returns 400 without opening
the socket; an upstream failure returns 502 before the downstream connection is
upgraded.

## Components

`internal/config` resolves proxy flags over environment values, validates the
provider identifier, and verifies the Unix socket.

`internal/wrapper` classifies invocations of a transparent executable named
`codex`. Its three-stage parser recognizes supported common configuration
options before `app-server`, before `proxy`, and after `proxy`. It intercepts
every effective `app-server proxy` invocation, including malformed ones, and
resolves a distinct real Codex executable for all other commands. File-identity
checks skip symlink and hard-link recursion.

`internal/transport` adapts stdin/stdout to one full-duplex `net.Conn`, accepts
the downstream HTTP Upgrade, and dials another WebSocket through a custom Unix
socket `http.Transport`. It removes standard hop-by-hop headers and WebSocket
headers generated by the client library. End-to-end headers, the request path,
query, negotiated subprotocol, and downstream `request.Host` are preserved.

`internal/rewrite` validates one WebSocket text-message payload and rewrites
`thread/start`, `thread/resume`, `thread/fork`, and `thread/list`. Unknown valid
messages are returned byte-for-byte.

`cmd/codex-provider-switcher` owns mode selection, signal cancellation, help,
version output, diagnostics, and process exit codes. Delegated commands replace
the wrapper process with `syscall.Exec`.

## Wrapper Grammar And Socket Resolution

The wrapper consumes repeatable `-c`/`--config`, `--enable`, and `--disable`
options at the top-level, app-server, and proxy layers. `--strict-config` is
accepted at the first two layers. Once the effective command is identified as
`app-server proxy`, unsupported or malformed arguments fail closed; known
non-proxy commands and proxy help delegate unchanged.

An explicit proxy `--sock` wins over `CODEX_PROVIDER_SWITCHER_SOCKET`, which
wins over `$CODEX_HOME/app-server-control/app-server-control.sock`. If neither
environment value is set, the wrapper uses
`$HOME/.codex/app-server-control/app-server-control.sock`. Direct mode remains
unchanged and requires `--socket` or `CODEX_PROVIDER_SWITCHER_SOCKET`.

## Message Flow

After both handshakes, two concurrent pumps run:

```text
Desktop text   -> decode complete message -> rewrite targets -> UDS text
Desktop binary -> no parsing                              -> UDS binary
Desktop        <- no parsing or rewriting                 <- app-server
```

The WebSocket library handles client masking, 7/16/64-bit payload lengths,
fragment reassembly, ping, pong, and close control frames. Message frame
boundaries may change, but message type and payload semantics are preserved.

`permessage-deflate` is disabled on accept and dial, including when Desktop
offers it. Both connections enforce a 64 MiB message limit. stdin/stdout writes
loop over short writes, and no layer assumes an operating-system read matches
an HTTP line, frame, or message.

## Close And Cancellation

When one side sends a valid close code and reason, the bridge sends the same
close to the opposite connection, then cancels the remaining pump and releases
both connections. Routing-policy, size, and transport errors close both sides
with a sanitized diagnostic. Signal cancellation closes the stdio connection
and both WebSockets without touching the separately managed daemon.

There is no child proxy process to signal, kill, or reap. Non-proxy Codex
commands use `exec`, so they naturally retain standard streams, environment,
signals, and exit behavior.

## Routing Policy

The provider identity is the SSH entry point's routing authority:

- `thread/start`, `thread/resume`, and `thread/fork` receive the selected
  `params.modelProvider`.
- `thread/list` receives an empty `params.modelProviders` list so tasks from all
  configured providers remain visible.
- `turn/start`, `model/list`, unknown methods, server messages, and binary
  messages are not rewritten.

A missing provider or unsafe target `params` shape fails closed. Diagnostics
never format message bodies, prompts, handshake values, environment contents,
or credentials.

The remote SSH account and every process running as the same Unix user are
trusted at the account-authority level. Such a caller can already bypass the
wrapper, connect to the control socket, or replace its own environment. The
switcher therefore guarantees routing correctness, not authorization against a
hostile same-user process. Setuid, privileged-socket, and restricted-shell
deployments require a separate security design.

## Daemon And Task Model

Every switcher process connects to one separately managed app-server socket.
The project neither starts an app-server nor reads its SQLite database. This
keeps one daemon and one writer for one `CODEX_HOME` and task store.

Different tasks can use different providers concurrently. One loaded task must
not be operated concurrently through different providers. Sequential resume
through another provider remains supported because context comes from the
shared persisted thread history.

## Release Model

CI runs formatting, unit and real WebSocket-over-UDS integration tests, vet,
the race detector, and Linux/macOS cross-builds. Tag pushes matching `v*`
repeat the quality gate and package:

- `linux/amd64`
- `linux/arm64`
- `darwin/amd64`
- `darwin/arm64`

Each archive includes the binary, README, MIT license, and
`THIRD_PARTY_NOTICES`. The build job lists each completed archive and rejects it
unless the third-party notice is present. The publication job is the only job
granted `contents: write` and attaches one SHA-256 file per archive.
